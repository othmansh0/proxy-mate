### Research and implementation decisions

[Proxyman MCP](https://proxyman.com/docs/mcp) documents a local authenticated app service and a separate stdio forwarding process, plus setup/discovery guidance. Our default entry now follows that separation: `src/client.mjs` has no engine, routing mutation, runtime lock or capture-memory restart guard. The old in-process engine requires `--in-process`. Client termination cannot invoke proxy cleanup. Offline help and tool discovery stay available when the daemon is unavailable.

[Claude Code's MCP documentation](https://code.claude.com/docs/en/mcp) distinguishes a stdio process exit from a remote-service outage: exited stdio servers are marked failed, while server instructions help tool search discover the right operation. Therefore recovery stays behind the live bridge. `get_started`, `search_docs`, and `list_setup_workflows` provide short built-in guidance, exact next-call arguments and explicit platform limits. Long tools emit monotonic progress heartbeats; their existing operation deadlines remain bounded.

Proxyman's [proxy helper](https://proxyman.com/docs/basic-features/proxy-setting-tool) handles system proxy changes/restoration; its [localhost guidance](https://proxyman.com/docs/troubleshooting/couldnt-see-any-request-from-localhost-server) also describes the normal system-proxy bypass. Our protection is an independent unprivileged guardian, scoped PAC leases and a captured reverse proxy. This is our recovery design, not a claim about undocumented Proxyman internals. A native privileged helper or [transparent Network Extension](https://proxyman.com/docs/advanced-features/network-extension) is a separate signed platform product, not something MCP transport supplies.

### Defects fixed in 0.8.0

- **Process lifetime:** default clients cannot silently become capture owners; offline onboarding works without creating state/locks. The daemon and guardian are separate supervised LaunchAgents. The existing authenticated reconnect and unknown-outcome mutation protections remain in place.
- **Routing defaults and failure:** no domain scope means no system routing. Broad routing needs an additional explicit grant. Selected hosts use `PROXY; DIRECT`, and routing has a one-hour default lease (1–86400 seconds). This permits fallback in PAC-aware clients when the listener is unavailable; it is not a universal guarantee for clients that ignore PAC or reject the active CA.
- **Wrong service / conflicting proxies:** resolve macOS's primary IPv4/IPv6 service instead of preferring enabled Wi-Fi. Refuse to guess on an unresolved service, protect existing automatic/manual proxies, and snapshot the currently owned setting again when another tool has changed it. Only owned settings are restored. Host CA trust is required before system routing.
- **Partial setup and malformed recovery:** verify that networksetup actually applied the PAC and roll back partial changes. The old `URL:\\s*(.*)` parser could consume a following `Enabled: No` line when the URL was empty. Horizontal-space parsing and null normalization fix the failed-restoration path. Lease expiry and explicit external changes have regression coverage.
- **Hard crashes/hangs:** the guardian acquires exclusive runtime ownership before restoring a dead owner's routing. A sustained health failure can restart only the recorded installed daemon, with PID, role and exact runtime-entry verification. PID reuse and unrelated servers are preserved. The bridge remains connected during recovery; an outage longer than its wait is a tool error. A guardian cannot guarantee recovery if macOS disables its job or denies network-setting changes.
- **Install/update reliability:** failed activation/readiness restores previous plist files and previously loaded jobs; stable publication occurs last. Runtime status includes executable identity, source/dependency hashes and bounded separate daemon/guardian event journals. CLI domain-file contents are resolved during installation instead of leaving launchd dependent on a protected Documents path.
- **Local backend capture:** the old reverse proxy bypassed the engine. It now traverses capture/rules, returns a scoped `local_url`, propagates cancellation, and tracks loopback sockets so cleanup does not wait indefinitely. Regression proves upstream response capture, a mock response and listener removal without system routing.
- **Operator safety:** doctor preserves a healthy daemon and cannot use `force` to kill an unverified listener. Capture readiness is reported in separate stages; a running service or previously observed flow is not attributed automatically to the intended app. The public body-size limit now matches the engine's 50 MiB limit.
- **Runtime support:** Node 25 in the old Claude registration was end-of-life. Local setup uses Homebrew Node 24 LTS without changing the shell's default Node. CI now targets maintained 22/24/26 lines. Node's [release policy](https://nodejs.org/en/about/previous-releases) recommends maintained LTS releases for production.

### REA decision

[REA](https://github.com/morluto/rea) provides local application/binary investigation and evidence-backed inspection. It can help answer a narrow unresolved question about native proxy routing, a Network Extension or an Android companion app. Native inspection needs a supported analysis provider; it does not supply a capture engine or make simulator certificate/proxy setup reliable automatically.

It is not needed for this first repair. Proxyman publishes its [Simulator setup](https://proxyman.com/docs/debug-devices/ios-simulator), [Android setup](https://proxyman.com/docs/debug-devices/android-device) and [automatic Android script workflow](https://proxyman.com/docs/debug-devices/android-device/automatic-script-for-android-emulator). The installed application also contains a readable Android script at `Contents/Frameworks/ProxymanCore.framework/Resources/install_certificate_android_emulator.sh`. It exposes the important distinctions directly: per-device ADB work, proxy setup/revert, root-dependent CA installation with Android/Conscrypt mount namespaces, and an optional companion VPN route. There is no need to decompile a native application to discover those requirements.

Recommendation: keep Mockttp for the present HTTP(S) contract, implement and measure the missing platform adapters, and use Proxyman as a behavioral reference on controlled test traffic. Revisit REA for a specific unanswered native behavior with an expected experiment/result. Do not introduce it as a runtime dependency of this proxy. The current REA 6.8.0 npm metadata requires Node `^22.23.4 || ^24.22.1 || >=26.12.1`; the audit's existing Node 26.8.1 does not meet that range. No REA package, native provider or global agent configuration was installed during this assessment.

### Implementation order and release gates

1. **Shared service reliability.** Deploy the required-daemon registration, verify both Claude and Codex share its PID/session, and retain a structured restart/exit journal with runtime fingerprints. Exercise clean stop, SIGKILL, startup failure, cancellation, upgrades and failed-upgrade rollback. Gate: a client exit never ends capture for another client; a restart reconnects or returns an actionable bounded outage; an ambiguous mutation is never silently repeated. The automated client/SIGKILL/partial-response portions are covered by this change; deployment and rollback qualification remain open.
2. **iOS capture readiness.** Fix service selection and define a deliberate localhost path. Add separate tooling/proxy/trust/routing/app-traffic results rather than a single optimistic Boolean. Check a nonce-bearing native request through the actual running engine, then inspect a request from the intended app. Gate: cold/warm app starts, simulator restart, a second simulator, cache behavior, VPN/service switching and restored prior settings. Preserve the existing distinction between trusted interception and pinned/proxy-bypassing apps.
3. **Android emulator lifecycle.** Discover ADB both on PATH and in the selected Android SDK; require an explicit serial when multiple devices are present. Journal the existing proxy value and only restore settings/forwarding still owned by this runtime. Prefer a scoped `adb reverse` route to the loopback listener where supported; report host mapping explicitly. Provide debug-only app trust using [Android Network Security Configuration](https://developer.android.com/privacy-and-security/security-config). Do not infer native-app trust from browser success or from installing a user CA alone. Add an independent root-capable emulator lane for system CA trust, including Android 14+ Conscrypt namespaces. Google Play/unrooted images must have an explicit supported debug-app path or a measured companion/VPN solution. Gate: native HTTPS success/failure controls, real captured flow, mock and breakpoint effect, rollback, reboot, ADB reconnect and two emulators. Physical devices and Flutter/native stacks that bypass HTTP proxy settings require separate acceptance.
4. **Workflow/engine qualification.** Cover HTTP/1.1 and HTTP/2, gzip/Brotli, chunked and large uploads/downloads, SSE/streaming, WebSockets, binary/omitted bodies, TLS failure and passthrough, upstream failure, disk pressure and concurrent agents changing rules. Add rule ownership/expiry or equivalent conflict protection before treating conventions as isolation. Gate: an 8-hour mixed soak followed by a multi-day real-app trial with explicit thresholds for dropped captures, unfinished flows, failed persistence, latency, RSS and duplicate mutations. HTTP/3 and TUN/VPN coverage would be a separately designed capture backend, not a small ADB wrapper.
5. **Release qualification.** Run the supported Node/macOS/Xcode/Android matrix, test a clean machine install and migration/rollback, set package identity/version, and verify packed artifacts and diagnostics. Retire EOL Node versions from the production support promise. Declare the exact supported workflows; a mature desktop GUI, general scripting, HTTP/3 and arbitrary app interception are not established by MCP feature parity.

Replacement acceptance should be a checked evidence matrix, not another declaration that the test count is large. Keep Proxyman available until the chosen iOS and Android gates pass.

## Verification

- 190 passing tests on Node 24 LTS, the installed Node 25 binary, and local Node 26. Coverage includes real stdio MCP workflows, memory-pressure cleanup, checkout-independent runtime installation, dependency symlinks and owned snapshot retention; the final stable-entry-point publication checks also passed on Node 25.
- Isolated daemon integration: readiness, competing owner refusal, SIGTERM cleanup, restart, SIGKILL, stale-lock recovery and new token. It does not change host trust or routing.
- Native Simulator probe: untrusted test CA failed with `NSURLErrorDomain -1202`; after targeted root import, the same URLSession check returned HTTP 200 with system trust verified. A dedicated test CA and disposable Simulator were used, not a developer app/device. Automatic app PAC routing is explicitly a separate check.
- 10,000-flow storage benchmark: append/update/pagination and durable row storage exercised.
- Five-minute isolated mixed-HTTP soak: 11,339 requests, 594 live JSON-rule updates, 150 breakpoint resolutions, zero failures and zero dropped capture events; peak process RSS 215,924,736 bytes (~206 MiB). Mix includes passthrough, mocks, gzip/spilled bodies, session retention and restart/hydration. This is not a real-app or multi-day certification. Repeat with `npm run test:soak -- 3600` (up to 86,400 seconds); CI runs 60 seconds on changes and 300 seconds weekly.
- Installed LaunchAgent validation: authenticated readiness from the private runtime snapshot; all 105 tools and the new workflow prompt discoverable through the stable MCP entry point; the same client reconnected after a graceful supervised restart with a new daemon PID. Persistence healthy, zero capture drops, and the existing CA fingerprint unchanged. The old stderr/stdout and plist were backed up to `/private/tmp/proxy-before-agent-upgrade.qjnMyf` before log retention activated; this is a temporary local backup, not a shipped artifact.
- Production dependency audit: zero reported vulnerabilities after updates. Package-content dry run includes the Swift probe, CLI verifier, and both new guides.

Run the complete suite after dependency changes. CI's Node 20/22/24 matrix remains important; a local run on one Node version does not establish all-version compatibility. The real Simulator probe is manual because hosted CI does not always provide a booted compatible runtime.

## Remaining limitations / follow-up validation

- No multi-day real-app soak or proof across every Xcode/iOS/VPN combination; pinning and proxy-bypassing app stacks still need app-specific debug configuration.
- Rules are ordered alternatives, not a middleware chain. Disable an overlapping mock before using a breakpoint on that endpoint. Clients share rule/session state; use task-specific rule IDs and clean up only your own rules.
- Bounds and the RSS restart guard are not a hard OS memory ceiling. A sudden spike can beat the sampler; inspect capture-drop/persistence diagnostics and prefer narrow API routing.
- Oversized/omitted bodies cannot be reconstructed. Empty chunked captures are conservatively unavailable, including legitimately empty chunked responses; supply explicit mock JSON when necessary.
- Captures are decoded/redacted HTTP representations, not byte-identical wire recordings. Spilled text replay works; stored binary replay requires sensitive-data authorization, and redacted replay deliberately omits real credentials.
- PAC drift is detected on the recorded macOS network service but never forcibly overridden. VPN/service changes may require explicit operator rerouting.
- Corrupt/unreadable CA journals or disk failure still require repair; automatic recovery does not bypass filesystem errors or grant trust to an app with certificate pinning.
- Log rotation checks every 30 seconds, so active logs can temporarily exceed 5 MiB; only the newest 5 MiB of an oversized stream is retained per archive.
- npm advisories remain time-sensitive; scheduled weekly audits help detect new reports but do not prove absence of vulnerabilities.
